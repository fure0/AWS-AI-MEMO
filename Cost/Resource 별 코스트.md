## WAF

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| Web ACL | **$5 / 월** | **₩6,750 / 월** | WAF 정책 묶음(ACL) 1개 유지 비용 |
| Rule / Rule Group | **$1 / 월** | **₩1,350 / 월** | ACL에 붙인 Rule 1개, 또는 Rule Group 1개 |
| 요청 검사 | **$0.60 / 100만 요청** | **₩810 / 100만 요청** | WAF가 검사한 HTTP(S) 요청 |

- ACL = **Access Control List** (접근 제어 목록)
  - 예: 회사 IP만 허용 / 해외 IP 차단 / `/admin`은 내부망만 접근 — 누가·무엇을 허용·차단할지 적어둔 목록
- Web ACL = 웹 요청을 허용/차단하는 규칙들의 묶음
- Rule = 단일 규칙 1개 (예: `/admin` 차단, IP 허용)
- Rule Group = 여러 Rule을 묶어 재사용하는 세트
  - **직접 만든 Rule Group**: 그룹 $1 + 안쪽 Rule 개수 × $1 (묶어도 절약 안 됨, 오히려 +$1)
  - **AWS Managed Rule Group**: ACL에 붙인 그룹 1개 = $1 (안쪽 규칙은 개수만큼 안 냄)

```text
Web ACL  (상자)
 ├─ Rule 1        ← 개별 규칙
 ├─ Rule 2
 └─ Rule Group    ← 여러 Rule을 묶은 세트
      ├─ Rule A
      └─ Rule B
```

예: ACL 1 + Rule 5 + 1천만 요청 ≈ $5 + $5 + $6 = **$16/월 (≈ ₩21,600)**

| Latency-based Query | **$0.60 / 100만 쿼리** | **₩810 / 100만 쿼리** | 사용자와 가장 가까운(응답 빠른) 리전으로 안내 |
| Geolocation Query | **$0.70 / 100만 쿼리** | **₩945 / 100만 쿼리** | 사용자 국가/지역 기준으로 대상 선택 |

```text
Hosted Zone  (예: example.com)     ← 존 유지 $0.50/월 (₩675)
 ├─ A     www     → 1.2.3.4        ← 조회 시 Standard Query 과금
 ├─ CNAME api     → api.other.com
 └─ Alias www     → CloudFront     ← Alias 조회는 무료

사용자  ── "www.example.com IP 뭐야?" ──▶  Route53  ── IP/대상 응답 ──▶ 사용자
                                              │
                                              ▼
                                    CloudFront / ALB / EC2 등으로 접속
```

**Latency-based Routing이란?**

여러 리전에 서버가 있을 때, Route53이 “이 사용자에게 지금 더 빠른 쪽”을 골라 주는 DNS 방식.

```text
서울 사용자  → 서울 리전 서버로
도쿄 사용자  → 도쿄 리전 서버로   (지연이 더 낮은 쪽)
```

지리(나라)가 아니라 **실제 네트워크 지연(latency)** 기준으로 고른다.  
Geolocation은 “한국 사용자는 한국 서버”처럼 **위치** 기준, Latency는 “어디가 더 빠른지” 기준.

참고: ALB/CloudFront 등 Alias A/AAAA 쿼리는 **무료**.

## ALB

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| ALB 자체 | **$0.0225 / 시간** (~$16.4/월) | **₩30 / 시간** (~₩22,000/월) | 로드밸런서 켜둔 시간 |
| LCU | **$0.008 / LCU-시간** | **₩11 / LCU-시간** | 연결·처리량·규칙평가 사용량 |

- LCU = **Load Balancer Capacity Unit** (로드밸런서 용량 단위)
- ALB가 얼마나 바쁜지를 재는 요금 단위. 아래 4개 중 **가장 큰 값**이 그 시간의 LCU
- **4개를 각각 합산해서 내지 않음.** 가장 바쁜 지표 1개만 요금에 반영 (max, not sum)

1 LCU ≈ 다음 중 가장 큰 값:

- 신규 연결 25/초
- 활성 연결 3,000/분
- 처리량 1 GB/시간
- Rule 평가 1,000/초

```text
예) 어떤 1시간 동안 측정값이
  신규 연결 = 0.5 LCU
  활성 연결 = 0.2 LCU
  처리량   = 1.5 LCU   ← 최대
  Rule 평가 = 0.8 LCU

→ 그 시간 LCU = 1.5 만 과금
  (0.5+0.2+1.5+0.8 = 3.0 이 아님)
  ≈ $0.012 (₩16) / 그 시간
```

왜 max인가: 트래픽이 늘면 연결·처리량·규칙평가가 같이 오르는 경우가 많아서, 4개를 다 합치면 같은 부하를 중복 과금하게 됨. 그래서 “병목이 된 지표”만 센다.

여기서 **규칙(Rule)** = ALB Listener Rule (어디로 보낼지 정하는 라우팅 규칙). WAF 규칙과 다름.

```text
사용자
  │
  ▼
ALB  (시간당 $0.0225 · ₩30)
  │  Listener Rule로 경로 분기
  ├─ /api/*    → API 타겟그룹  → ECS/EC2
  ├─ /admin/*  → Admin 타겟그룹 → ECS/EC2
  └─ 그 외     → Web 타겟그룹   → ECS/EC2

과금 포인트:
  · ALB 켜둔 시간              → $0.0225/시간 (₩30)
  · 연결·처리량·Rule 평가 중 최대 → LCU ($0.008 · ₩11 / LCU-시간)
```

요청 1건이 위 규칙들과 얼마나 매칭 비교되는지 세는 게 **Rule 평가**.  
규칙이 많을수록(또는 요청이 많을수록) 평가 수가 늘어 LCU에 영향을 줌.

## ECS

ECS 자체 관리 요금 **없음** (EC2/Fargate 비용만).

```text
ALB
  │
  ▼
ECS Cluster
  └─ Service
       └─ Task (컨테이너 실행 단위)
            ├─ vCPU
            └─ Memory

실행 방식에 따라 과금이 갈림:

  [Fargate]  Task에 할당한 vCPU·Memory 시간만 과금
             (서버 관리 없음)

  [EC2]      ECS 요금 $0 + EC2 인스턴스·EBS 요금
             (서버는 내가 띄움)
```

## CodePipeline

V1 / V2는 소프트웨어 버전 번호가 아니라 **파이프라인 타입(과금·기능 모드)** 이다.  
생성 시 타입을 고르고, 지정 안 하면 기본이 **V1**.

| | V1 | V2 |
|---|---|---|
| 과금 | 그달 돌린 파이프라인당 **$1/월 (₩1,350)** | 액션 실행 **분당 $0.002 (₩2.7)** |
| 특징 | 단순 고정비 | 트리거·변수 등 기능 더 많음 |
| 유리한 경우 | 자주·오래 도는 파이프라인 | 가끔·짧게 도는 파이프라인 |

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| V1 Active Pipeline | **$1 / 파이프라인 / 월** | **₩1,350 / 월** | 그달 1회 이상 실행된 파이프라인 |
| V2 Action 실행 | **$0.002 / action-분** | **₩2.7 / action-분** | 스테이지 안 액션이 돌아간 시간 |

```text
Source (GitHub/CodeCommit)
  → Build (CodeBuild)
  → Deploy (ECS/…)

V1: 파이프라인 자체가 그달 돌았으면 $1 (₩1,350)
V2: 각 액션이 돌아간 분 × $0.002 (₩2.7)
```

참고:

- V1: 생성 후 30일 무료, 월 1개 파이프라인 프리티어
- V2: 월 100 action-분 프리티어
- Manual Approval / Custom Action은 V2에서 시간 과금 제외
- 아티팩트 S3 저장·연결된 다른 서비스 비용은 별도

## CodeBuild

빌드가 돌아간 **시간(분)** × 선택한 컴퓨팅 타입 단가.

| 타입 (Linux EC2 On-Demand) | 스펙 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|---|
| general1.small | 2 vCPU / 4 GiB | **$0.005 / 분** | **₩7 / 분** | 가벼운 빌드 (가장 흔함) |
| general1.medium | 4 vCPU / 8 GiB | **$0.01 / 분** | **₩14 / 분** | Docker·중간 빌드 |
| general1.large | 8 vCPU / 16 GiB | **$0.02 / 분** | **₩27 / 분** | 무거운 컴파일 |

```text
CodePipeline / 수동 실행
  │
  ▼
CodeBuild
  · 소스 pull
  · docker build / 테스트
  · 이미지 push → ECR
  · 로그 → CloudWatch (별도)

과금 포인트:
  · 빌드 시작~종료 분 수 × 컴퓨팅 단가
  · 대기/실패해도 돌아간 시간은 과금
```

예: small로 하루 10번 × 5분 = 1,500분/월 → 1,500 × $0.005 = **$7.5/월 (≈ ₩10,000)**  
(프리티어 100분 제외 시 약 $7 · ₩9,500)

참고:

- 월 100분 프리티어 (small / arm.small)
- 로그(CloudWatch), 아티팩트(S3), KMS는 별도

## ECR

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| Private 이미지 스토리지 | **$0.10 / GB-월** | **₩135 / GB-월** | 리포지토리에 쌓아 둔 이미지 용량 |
| 같은 리전 pull (ECS/Fargate/EC2 등) | **$0** | **₩0** | 같은 리전에서 이미지 받기 |
| 인터넷 / 다른 리전으로 전송 | 인터넷 DTO 요금 | (DTO에 따름) | 리전 밖·외부로 나갈 때 |
| Push (업로드) | **$0** (전송 In) | **₩0** | 빌드가 이미지 올리는 비용은 보통 $0 |

```text
CodeBuild
  │  docker push
  ▼
ECR Repository          ← 스토리지 $0.10/GB-월 (₩135)
  │  docker pull
  ▼
ECS / Fargate / EC2     ← 같은 리전이면 전송 $0

과금 포인트:
  · 이미지 몇 GB를 얼마나 오래 보관했나 → 스토리지
  · 같은 리전 배포 pull                 → $0
  · 다른 리전·인터넷으로 나가면         → DTO
```

참고:

- 태그 없는 old 이미지도 삭제 전까지 스토리지 과금 → Lifecycle Policy로 정리하면 절약
- Public ECR은 스토리지/전송 프리티어가 따로 있음 (Private와 별개)

## CloudTrail

계정/리소스에서 **누가 무엇을 했는지** 기록하는 감사 로그.  
Trail로 S3에 계속 쌓을 때 이벤트 종류별로 과금이 갈린다.

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| Management 이벤트 1번째 복사 | **$0** | **₩0** | CreateVpc, IAM 변경 등 제어면 이벤트 첫 전달 |
| Management 이벤트 추가 복사 | **$2.00 / 10만 건** | **₩2,700 / 10만 건** | Trail을 여러 개 두어 같은 관리 이벤트를 또 보낼 때 |
| Data 이벤트 | **$0.10 / 10만 건** | **₩135 / 10만 건** | S3 GetObject, Lambda 호출 등 데이터면 (첫 건부터 유료) |
| Network activity 이벤트 | **$0.10 / 10만 건** | **₩135 / 10만 건** | VPC Endpoint 등 네트워크 활동 로그 |
| Insights (Management 분석) | **$0.35 / 10만 건** | **₩473 / 10만 건** | 이상 패턴 탐지용 분석 (옵션) |

```text
AWS API 호출 (콘솔/CLI/SDK)
  │
  ▼
CloudTrail
  ├─ Event history (최근 90일)     ← 조회 무료
  │
  └─ Trail ──전달──▶ S3 버킷
       │
       ├─ Management (1st copy)   ← $0
       ├─ Management (2nd+ copy)  ← $2 / 10만 건
       ├─ Data events             ← $0.10 / 10만 건
       └─ Network events          ← $0.10 / 10만 건

과금 포인트:
  · 관리 이벤트 Trail 1개(리전당 첫 복사) → 보통 $0
  · S3 객체/Lambda 등 Data 이벤트 ON     → 건수 × $0.10/10만
  · 로그 파일 보관                        → S3 스토리지 별도
```

**Management vs Data**

| 종류 | 예 | 기본 |
|---|---|---|
| Management | IAM 정책 변경, EC2/VPC 생성, 콘솔 로그인 | Trail 기본 ON, 첫 복사 무료 |
| Data | S3 `GetObject`/`PutObject`, Lambda Invoke | 기본 OFF, 켜면 전부 유료 |

예: Data 이벤트 1,000만 건/월 → 10,000,000 / 100,000 × $0.10 = **$10/월 (≈ ₩13,500)**  
(+ 로그가 쌓이는 S3 스토리지 비용)

참고:

- 콘솔 Event history 90일 조회는 **무료**
- Trail 로그를 담는 **S3·KMS 비용은 CloudTrail 요금과 별도**
- Data 이벤트는 Advanced selector로 버킷/함수 단위 필터링해 건수 줄이는 게 절약 포인트
- Organization Trail + 계정 Trail을 같이 쓰면 Management **추가 복사** 과금이 날 수 있음

## CloudWatch

메트릭·로그·알람·대시보드.  
ECS/ALB/CodeBuild 로그가 여기로 많이 들어와서 **로그 수집비가 제일 잘 큼**.

### Logs

| 항목 | 단가 (서울) | 원화 (대략) | 설명 |
|---|---|---|---|
| 로그 수집 Standard | **$0.76 / GB** | **₩1,026 / GB** | Log Group으로 들어온 로그량 (수집 시 1회) |
| 로그 수집 Infrequent Access | **~$0.38 / GB** | **~₩513 / GB** | 조회 적은 로그용 (기능 제한, 수집 반값) |
| 로그 보관 (압축 후) | **~$0.03 / GB-월** | **~₩41 / GB-월** | Log Group에 쌓아 둔 용량 |
| Logs Insights 조회 | **$0.005 / GB scanned** | **₩7 / GB** | 쿼리할 때 스캔한 데이터량 |

### Metrics · Alarms · Dashboard

| 항목 | 단가 | 원화 (대략) | 설명 |
|---|---|---|---|
| Custom Metric (처음 1만개) | **$0.30 / 메트릭 / 월** | **₩405 / 메트릭 / 월** | 내가 보낸 커스텀·Detailed Monitoring |
| AWS 기본 메트릭 | **$0** | **₩0** | EC2/ALB/S3 등이 기본으로 보내는 메트릭 |
| Alarm (Standard) | **$0.10 / 알람-메트릭 / 월** | **₩135 / 월** | 임계값 감시 1개 |
| Custom Dashboard | **$3 / 대시보드 / 월** | **₩4,050 / 월** | 직접 만든 대시보드 (3개까지 무료) |

```text
ECS / ALB / CodeBuild / 앱
  │  로그·메트릭 전송
  ▼
CloudWatch
  ├─ Logs
  │    · 수집 $0.76/GB (서울)     ← 보통 비용의 큰 부분
  │    · 보관 ~$0.03/GB-월
  │    · Insights 조회 $0.005/GB
  │
  ├─ Metrics
  │    · AWS 기본 $0
  │    · Custom $0.30/개·월
  │
  └─ Alarms / Dashboards
       · Alarm $0.10 · Dashboard $3

과금 포인트:
  · 로그를 얼마나 쏟아 붓나     → 수집 (가장 큼)
  · 얼마나 오래 보관하나       → 보관 + retention 설정
  · 커스텀 메트릭·알람 개수    → 개수 × 월 단가
```

예:

- 로그 100 GB/월 수집 (Standard) → 100 × $0.76 = **$76 (≈ ₩102,600)**
- Custom metric 20개 → 20 × $0.30 = **$6 (≈ ₩8,100)** (무료 10개 제외 시 10 × $0.30 = $3)

참고 (프리티어 · 절약):

- 로그 월 **5 GB** 수집/보관/스캔 무료
- Custom metric **10개**, Alarm **10개**, Dashboard **3개** 무료
- ECS/앱 로그는 **retention(보관 기간)** 안 줄이면 보관비가 계속 쌓임
- 자주 안 보는 로그는 Infrequent Access / 필터로 수집량 줄이기
- 서울 로그 수집($0.76)은 us-east-1($0.50)보다 **비쌈**
